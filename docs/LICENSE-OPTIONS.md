# 许可证选择（待决定）

尚未添加 LICENSE，本文件只是比较，不对源码授予任何许可。没有选定许可证时不能称为已经完成开源授权；参见 [GitHub 许可证说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)。

| 选项 | 下游使用 / 分发的主要条件 | 对 MML 的取舍 |
| --- | --- | --- |
| [MIT](https://choosealicense.com/licenses/mit/) | 宽松；保留版权及许可声明；允许商业使用、修改和闭源分发 | 最短、传播与复用成本低，符合极简单文件定位；不会要求公开修改源码 |
| [Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0) | 宽松；明确专利授权及终止条款；保留声明、标明修改，并在存在 NOTICE 时按要求保留相关说明 | 适合更重视明确专利条款的项目；文本与合规说明更长 |
| [GPL-3.0](https://choosealicense.com/licenses/gpl-3.0/) | 强 copyleft；分发受覆盖的修改 / 衍生程序通常需遵循同一许可证并提供相应源码、保留声明及标明修改 | 适合要求分发的改进继续开放的目标；下游组合与分发义务更严格，私人修改不等同于必须公开 |

**建议优先选 MIT**：本项目以轻量、复制传播、低维护成本为目标。如果更看重明确专利保护，可选 Apache-2.0；如果希望分发的衍生版本也保持开放，可选 GPL-3.0。这是基于项目目标的选择建议，最终授权取决于权利人决定与实际代码来源。

决定时还需确认版权署名、年份及对全部收录代码的授权权利。不要把 Mojang、Microsoft、Adoptium 的软件或商标权一并声称为 MML 所有，也不要认为 MML 许可证替代运行时下载内容的条款。GPL 需明确选择 GPL-3.0-only 还是 GPL-3.0-or-later；不得自行替权利人选择。

本次不复制任何完整许可证正文、不添加 LICENSE、不写“本项目已采用 MIT”等声明。待所有者明确决定后，再加入对应原文并更新 README 和发布材料。
